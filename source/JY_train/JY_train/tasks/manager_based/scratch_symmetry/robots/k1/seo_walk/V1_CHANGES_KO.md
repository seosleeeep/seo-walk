# seo_walk_v1: 전진 보행을 위한 제약 완화 실험

2026-11-04 수정. Windows에서 작성했으며 서버 적용 및 학습 검증 전이다.
`seo_walk_v0`는 이전 학습의 비교 기준으로 유지한다.
v1은 아직 서버에서 학습하지 않았으므로 기존 v1 제안에 이번 변경을 합쳤다.

## 목적과 근거

- 낮은 속도에서 제자리걸음·회전, 높은 명령에서만 약간 전진한다는 관찰을 바탕으로 만든 실험이다. 원인을 확정한 것은 아니다.
- `feet_offset_x_l1`은 양발 앞뒤 간격의 목표(기본 0) 오차를 최대 0.1m까지 벌점 처리한다. 그 벌점은 명령 속도에 따라 감소한다. 0.2m/s 명령에서는 기존 계수의 약 75%가 남지만, 1.5m/s에서는 0이다. 이 비대칭이 저속 보폭을 억제할 수 있다.
- 머리 높이 고정 보상은 없다. `base_height`는 지면 기준 몸통 높이를, `lin_vel_z`는 몸통 수직 속도를 제약한다. 머리 관절 2개가 고정인 것과 월드 기준 머리 높이를 고정하는 것은 다르다.
- 발을 높이 드는 clearance는 수평 보폭과 다르므로 0.13m 설정을 높이지 않는다.

## 변경표

| 항목 | v0 | v1 | 목적 |
|---|---:|---:|---|
| x/y 추종 sigma (단독·복합 명령 모두) | 0.25 | 0.05 | 정지해도 받는 저속 추종 보상 감소 |
| feet_swing | 3.0 | 1.0 | 전진 없이 발만 드는 보상의 상대적 비중 감소 |
| action_rate | -1.5 | -0.75 | 관절 목표 변화 허용 확대 |
| feet_offset_x | -5.0 | -1.0 | 앞뒤 발 간격 제약 완화 |
| base_height | -30.0 | -10.0 | 몸통 상하 움직임 허용 확대 |
| lin_vel_z | -2.0 | -1.0 | 수직 속도 제약 완화 |
| root_acc | -0.0001 | -0.00005 | 몸통 가속도 제약 완화 |
| heading_drift | -1.0 | -2.0 | 회전 명령이 없을 때 방향 이탈 억제 |
| tracking_ang_vel | 1.0 | 1.5 | 명령 yaw 속도 추종 강화 |

계수의 절댓값만으로 실제 보상 비중을 비교하면 안 된다. 각 항목의 원시 값과 로그 기여량을 함께 확인한다.

20개 action, 78개 policy 관측, 기본 자세, 관절 제한, actuator, 토크·전력 페널티, 몸통 기울기 페널티와 넘어짐 종료 조건은 그대로다.
정책 입출력 크기는 v0와 같지만 보상이 달라져 새 학습 또는 미세조정이 필요하다. 기존 export 파일로 재생하는 것만으로 동작이 바뀌지 않는다.

## 학습과 검증

- Train task: `seo_walk_v1`, Play task: `seo_walk_v1-Play`
- 로그: `logs/rsl_rl/seo_walk_v1/`
- Play는 평지·로봇 1개·명령 (0.2, 0, 0), 관측 노이즈와 외부 push/kick 없이 평가한다. 그 외 startup/reset 랜덤화는 상속된다.
- 서버 복구 후 먼저 16환경·2 iteration 실행으로 환경 구성을 확인한다.
- 비교는 같은 시작 체크포인트·학습량·명령으로 한다. 기존 v0의 모델을 시작점으로 쓰려면 새 실험의 로그 경로와 이전 checkpoint 로드 경로를 구분해야 한다.
- 평가 명령: 전진 0.2 / 0.5 / 0.8m/s, 측방향 0, yaw 0. 별도로 정지와 회전 명령도 확인한다.
- 판단 기준: 실제 전진 속도, 측방향·yaw 오차, 넘어짐 횟수, 몸통 높이 범위, 학습 로그의 각 reward 기여량. 보폭이 커 보인다는 것만으로 성공 판정하지 않는다.
- 추종 sigma를 줄이면 큰 오차에서 학습 신호가 작아질 수 있고, 움직임 제약 완화는 진동·낙상을 늘릴 수 있다. 회귀하면 보상 그룹을 하나씩 되돌려 원인을 분리한다.
